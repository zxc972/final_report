# PrimateX Agent Knowledge

PrimateX is a T1 preprocessing and cortical reconstruction workflow for non-human primates, with a Human FastSurfer path for human T1 data.
It targets a complete, practical pipeline, with an emphasis on T1 structural preprocessing and surface reconstruction.

## Monorepo layout

- modules/neuro_pipeline: shell/Python scripts for neuro preprocessing and FreeSurfer-based reconstruction.
- modules/primx_seg: deep-learning segmentation (brain + white matter) and a router classifier.
- workflows/primx_cli/primx: unified CLI entry for all modules.
- modules/gui: web UI for pipeline orchestration.
- modules/agent: agent backend and skills registry.

## Key pipeline steps (primx)

- neuro preprocess-1: reorient, N4, optional denoise/average, resample.
- seg brain: brain extraction (brain_mask.nii.gz, brain.nii.gz).
- neuro acpc-align: FOV crop + AC-PC alignment.
- seg wm: white matter mask (wm.nii.gz).
- neuro preprocess-3: FreeSurfer recon initialization (combined 3-1 + 3-2).
- neuro rescale: rescale from fake 1mm to native resolution.
- neuro freesurfer2caret: GIFTI/CIFTI outputs + fs_LR registration.
- human fastsurfer: human cortical reconstruction using FastSurfer.

## Inputs and outputs

- Input T1 image is typically .nii or .nii.gz.
- Output directory is `<workspaceDirectory>`/`<subjectId>`.
- Logs for agent-run pipelines are written to `<outPath>`/logs/agent_pipeline_`<taskId>`.log.
- The directory structure is as follows:
  ```
    /Data/Project/Monkey001/               <-- often be the `-out_path`
    ├── T1.nii.gz                         Generated by neuro preprocess-1, which is the preprocessed T1
    ├── brain_mask.nii.gz                 Generated by DL brain extraction
    ├── wm.nii.gz                         Generated by DL WM segmentation
    ├── Monkey001/                         <-- FreeSurfer SUBJECTS_DIR, the name is `-subject_id`
    │   ├── mri/
    │   │   ├── orig.mgz
    │   │   ├── T1.mgz
    │   │   └── ...
    │   ├── surf/
    │   └── label/
    ├── tmp/                              (临时文件夹)
    └── ...
  ```

## Species and segmentation labels

- Neuro steps use species: Macaque/Chimpanzee/Marmoset (case-insensitive).
- cynomolgus and rhesus are accepted and treated as macaque settings.
- Human FastSurfer step uses human T1 input and supports optional `species=Human` in agent requests.
- Segmentation species values: rhesus, cynomolgus, chimpanzee, marmoset, human (case-insensitive).

## Segmentation model directory

- If modelDir is not provided, primx uses modules/primx_seg/models.
- Avoid passing a relative modelDir unless it is correct for the running environment.

## Router classifier

- primx seg router predicts species and image type (scalp vs brain) from a T1 image.

## Default workspace and onboarding

- The default workspace is `<repo>/tests` (overridable with the `AGENT_DEFAULT_WORKSPACE` environment variable).
- When the user has not provided a workspace directory or subject ID, follow this flow:
  1. Ask: "Do you want to use the default workspace, or do you have your own data directory?"
  2. If they accept the default (or provide their own path), call `workspace-ls` to list available subject IDs. Show the list.
  3. Ask: "Which subject would you like to process?"
  4. Once a subject is chosen, call `find-t1` to discover the T1 NIfTI file automatically.
     - If exactly one candidate is found, use it directly as `t1Path` and confirm with the user.
     - If multiple candidates are found, list them and ask the user to pick one.
  5. Ask which pipeline steps to run, or suggest a sensible full pipeline based on the species.
  6. Once all parameters are confirmed, launch the pipeline with `run-pipeline`.

## Agent behavior

- Use tools for pipeline execution and status checks.
- Ask for required inputs when missing.
- Prefer explicit parameters and confirm paths.
- Deep-learning segmentation is intentionally serialized at step scope: multiple pipelines may run concurrently, but only one `seg-brain` or `seg-wm` subprocess may hold the shared segmentation resource at a time.
- `Waiting for segmentation resource` is normal while another segmentation step runs. Do not retry or submit a duplicate, and do not tell the user that increasing `maxConcurrentTasks` will parallelize segmentation.
- All non-segmentation steps retain the normal pipeline concurrency configured by `maxConcurrentTasks`.
- Directory inspection: use `subject-tree` for broad overview questions (directory structure, full output layout, all produced files); use `subject-ls` for targeted lookups of a specific named subfolder. Avoid calling `subject-ls` multiple times in sequence to reconstruct a layout that `subject-tree` would return in one call.

# LightRAG 图文联合检索与原文检索实测（2026-10-20）

本轮已经完成真实 API 对照：8 个问题、两种检索方式、16 个回答；另对 3 个问题各补测两种上下文，共 6 个修订回答。结论是：**在当前小语料中，图文联合检索尚未显示优势。两组都能找到关键来源，但找到原文后，回答仍可能丢掉条件或扩大结论。** 图可以继续作为检索工具，现阶段不能把抽取关系或回答摘要直接变成 Agent 的参数决定。

本报告评价的是检索与知识使用，没有运行结构像分析，也没有修改重构后的产品 Agent、开发组或保留组数据。这里的图是本轮 LightRAG 原生抽取的独立实验图，不是把此前 GraphRAG 修订版或逐主张候选图改名为 LightRAG。

## 1. 实际采用了什么

参考 [LightRAG 论文](https://arxiv.org/abs/2410.05779) 和 [官方代码](https://github.com/HKUDS/LightRAG)，安装并运行 `lightrag-hku==1.5.7`：

- A：原生 `naive`，只检索原文向量。
- B：原生 `mix`，检索实体、关系及原文，并合并关联片段。
- 两组使用相同原文、问题、嵌入模型、回答模型、回答提示词；通过原生 `aquery_data` 保存实际召回，再交给同一个回答函数。不是分别调用两个不同的端到端问答模板。
- 回答 API：`https://inferaiapi.com/v1`，`deepseek-v4-pro`，temperature=0，关闭 thinking；密钥仅在服务器。
- 嵌入：本地 CPU 的 BGE-small-en-v1.5，384 维，FastEmbed 0.9.0，Qdrant ONNX 量化版本。公开权重从可达镜像下载，SHA256 与 Hugging Face 官方 LFS 记录一致。
- 15 个片段，切块 280 个 o200k token、重叠 50；每题最多 3 个最终原文片段。实体/关系候选 top_k=5，关闭 reranker。
- 两组原文上下文上限均为 1,600 token；B 额外允许实体 500、关系 700。实际长度另行统计。这是系统配置对照，**不是等 token 的图结构因果消融**。
- 抽取使用安装版原生 JSON 提示词，gleaning=0，没有把评审答案或 required_sources 交给模型。实际提示词、请求、原始回复均保存在 `http/`。

当前英文嵌入模型配英文问题，未检验中文检索。只运行一次，不是多随机种子或专家盲评。

## 2. 用了哪些材料

本轮复用上一阶段已保存并带哈希的 10 段原文，来自 7 个来源（1 篇研究论文、6 个教程/软件文档来源），没有把整个互联网或全部历史知识库纳入实验。

| 片段 ID | 内容及来源 | 本轮要检查的边界 |
|---|---|---|

| SBM_CACHE | [FreeSurfer GroupAnalysis](https://surfer.nmr.mgh.harvard.edu/fswiki/FsTutorial/GroupAnalysis) | qcache、fsaverage、通常使用多种 FWHM |
| STAT_BLOCK | [FSL randomise](https://fsl.fmrib.ox.ac.uk/fsl/docs/statistics/randomise.html) | 重复测量的条件适用性及配置块后才生效的限制 |

| NHP_M1 | 同上 | M1 参数要求目录，不可继承 wrapper 契约 |
| NHP_N4 | 同上 | generateN4 使用 M1 处理后的 T1，作为相关干扰/上下游材料 |
| CROSS_FINDING | [跨物种皮层变化与连接模式研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC7180052/) | 皮层扩张/迁移能解释的束与弓状束例外 |

LONG 的原文范围注明 FS 5.1/5.2/5.3/6.0 历史文档，不能代表服务器安装版本。PREEMACS 使用此前保存的 README 快照，不等于已核对安装软件的 CLI。完整片段和哈希见 `corpus.json`；加入检索的文档及哈希见 `indexed_documents.json`。

实际索引：**10/10 文档处理完成、15 个片段、86 个实体、73 条关系**。实体类型为 method 19、data 12、artifact 15、location 2、concept 31、content 3、creature 3、organization 1。这些是自动抽取数量，不是已审核的领域概念数量。

## 3. 原始两组对照结果

| 指标 | 原文 naive | 图文 mix |
|---|---:|---:|
| 有完整回答的问题 | 8/8 | 8/8 |
| 预标记关键来源均召回 | 8/8 | 8/8 |
| 关键来源槽位命中 | 9/9 | 9/9 |
| 回答中的逐条主张 | 34 | 38 |
| AI 辅助审查：片段范围内支持 | 29 | 33 |
| AI 辅助审查：部分支持/范围过强 | 5 | 5 |
| 引句逐字匹配 | 35/35 | 38/38 |
| 实际回答上下文平均 token | 637.4 | 1,587.1 |
| 上下文 token 范围 | 510–805 | 1,313–1,756 |

**73/73 引句都匹配，仍然存在语义问题。** 上表逐主张统计包含 qualification 的审查，但摘要矛盾、版本范围遗漏另在逐题审查中记录，不能用 29/34 或 33/38 直接替代完整回答准确率。

两组有 6/8 题的原文片段集合完全相同；其余 2 题也只是换入不同的附带片段，关键原文没有新增。这个语料已经出现原文检索的召回上限，不能据此断言大语料、多跳查询也不需要图。

按本轮完整回答标准，R01、R04、R08 两组都在片段范围内通过；其余五题核心知识通常已找到，但摘要、附加条件或版本范围仍有缺口。以下区分缺口的位置，不一律归因于检索。

| 问题 | 原文组 | 图文组 | 主要问题所在 |
|---|---|---|---|
| R01 跨物种弓状束例外 | 正确保留特定机制及例外 | 同样正确 | 本轮未发现核心结论错误 |
| R02 wrapper 与 M1 输入契约 | 核心正确；额外把示例参数当成必填 | 首句回答 Yes，后文又要求目录；还扩展了许可/参数要求 | 生成与摘要一致性；不是缺少原文 |
| R03 纵向比较对象 | 比较时间点输出正确，未带出历史版本 | 同样漏版本；额外生长限制有强化措辞 | 范围传递与生成 |
| R04 MRIQC 方向/阈值 | 方向正确，明确没有给定阈值 | 同样正确 | 本轮无虚构阈值 |
| R05 VBM 均衡范围 | 模板子集正确；摘要声称全部个体仍进入最终分析 | 模板子集正确；摘要也比片段证据更强 | 最终队列信息缺少，回答却扩大范围 |
| R06 儿童生长/eTIV | 假设、QC、读取位置正确；未区分文档版本和安装版 | 同样缺口 | 版本元数据已召回，但回答没正确使用 |
| R07 重复测量置换 | 找到块与 sometimes，但把难以适用强化为一般不适用 | 同样；摘要仍容易读成程序自动限制置换 | 图抽取弱化条件、回答再次压缩条件 |
| R08 qcache 与平滑 | 没有把 10 mm 当成统一必选值 | 同样正确 | 本轮无核心问题 |

其中 R05 并不是证明 FSL-VBM 的最终分析必须丢掉受试者。正确区别是：模板抽样规则只约束模板步骤；本片段不足以断言最终实际纳入哪些个体。应再找最终处理、设计和 QC 的依据。

## 4. 图里实际发现了什么问题

定向检查见 `graph_targeted_review.json`，不是对全部 73 条边的专家审核：

1. `Randomise—Repeated Measures` 的描述直接写“accommodates”，没有保留原文的 sometimes。这条边单独给 Agent 看，会高估适用性。
2. 块和 group_labels 有关联，但“配置后才限制块内置换”没有独立条件字段，主要藏在原文中。
3. 跨物种弓状束的负面发现被保留在关系描述中，这是正面结果；但 polarity 仍是自然语言，没有结构化负向字段。
4. 实例值 SUB01、命令路径等也被当成实体；还存在 Recon-All/Recon-all、preemacs.sif/Preemacs.Sif 两组大小写别名。不能用节点数量代表知识质量。

因此，后续保留 LightRAG 的抽取、索引和检索机制，同时在面向 Agent 的记录中携带原文、适用条件、例外、版本范围和“示例值”标记。不要把图中的无类型边直接转成参数约束。

## 5. 已追加的修正实测

针对 R02、R05、R07，**不改变检索结果和模型**，把输出改为：直接回答、已确认事实、条件、例外、未确定事项、来源范围。要求回答针对原始操作，不能用一个改造后的替代操作回答“可以”；命令示例也不能直接证明参数必填。

实际追加 6 次 API 调用，20/20 引句匹配。原始答案没有覆盖，文件分别在 `answers/` 与 `answers_contract_v2/`。

- R02 两组都改为明确的 No，并解释 wrapper 可以接文件、M1 需要目录，单文件应放入目录。没有继续添加必填许可证/参数推论。未知项措辞仍应区分已知文档契约与未测试的程序容错行为。
- R05 不再断言所有个体已经实际进入最终分析；明确结论只到模板子集的选择规则，最终队列仍需补证据。
- R07 恢复了原文的难易和 sometimes，但摘要仍没清楚带出“若已配置”；还不能当作软件会自动阻止错误置换的保证。

这轮属于**看到错误后的开发集修正**，不能宣称独立准确率提高，也不能证明增加几个提示词就能解决全部问题。修正有帮助，但仍需结构化参数检查和新的未见问题检验。

## 6. 怎么接入现有 Agent

已只读核对服务器代码：

- `/data/xuancheng/agent/modules/agent/backend/analysis_agent.py:281` 已有 search_knowledge、search_method_knowledge、read_knowledge。
- `/data/xuancheng/agent/modules/agent/backend/analysis_knowledge.py:203` 现有 search_method_knowledge 是已审核记录的词项排序，返回 source_segment_ids、scope、validation_state 等。
- 现有已审核发布包有哈希和回归检查，不能把此次自动抽取的候选图塞进去冒充已审核知识。

建议顺序：

1. **先接只读证据检索。** 保留现有已审核知识入口，新增候选研究证据入口，或在后端明确区分 reviewed/candidate 路由。用独立检索服务承载本轮依赖，不向 Agent 环境直接灌入整套实验依赖。
2. **返回证据包，不只返回答案。** 包含来源 ID、文档版本、片段原文/哈希、图中候选关系、条件、例外、未知项，以及 naive/mix 的实际召回轨迹。图派生陈述与原文要能区分。read_knowledge 继续按注册 ID 读取，不能接受任意服务器路径。
3. **与数据状态联合决定。** Agent 再调用现有数据检查工具，核对物种、模态、处理阶段、文件/目录、软件版本、表面/体积空间等；把“方法可用”和“这份数据满足条件”分开验证。
4. **再生成和检查脚本。** 参数必须可追溯到原文/工具帮助/数据检查。对输入类型、版本、空间和必需产物做确定性检查，避免仅依赖摘要；错误设计不能靠引用匹配通过。
5. **用开发任务串联验证后再扩展。** 先测真实数据状态 → 检索 → 参数 → 脚本生成；通过后再运行开发组。保留组两例继续不动。

目前优先保留原文检索作为稳定基线；涉及方法关系、上下游依赖、跨来源问题时再比较 mix。这里不是取消图，而是按实测让图承担确实有用的工作。

## 7. 接下来按什么顺序推进

1. 扩充与当前问题直接相关的完整段落：randomise 的重复测量示例和设计要求、FSL-VBM 最终统计阶段、PREEMACS 真实 CLI/安装版本、FreeSurfer 安装版对应文档。避免只拿摘要或零散示例判断完整流程。
2. 让版本/入口/阶段元数据随每个片段返回；将条件、否定、例外绑定到主张和原文，而不是另建孤立节点。先纠正本轮已发现的语义问题，再扩大图。
3. 扩大到含相似术语干扰的语料，增加跨段、跨文档和中文提问；预先冻结新题，设置无答案问题。对比 naive、mix，并加入等上下文预算和多次重复，才判断图是否有稳定收益。
4. 实测原文片段的语义条件覆盖率、参数契约正确率和不确定性表达，不能只测来源命中。已有 8 题保留为回归，不当盲测。
5. 按上一节接只读证据工具，再做 Agent 的数据状态和脚本链路。当前结果不支持跳过这些检查直接自动分析。

## 8. 用量、失败与复现

本轮累计 **61 次 LLM HTTP 尝试：45 次返回成功、16 次 429**。已知输入 69,637 token、输出 20,716 token，合计 **90,353 token**；16 次失败无 usage，不能记为零消费。另有 1 次模型列表 GET；本地嵌入不调用计费 API。未按价格换算金额，因为没有核对服务商实际账单。

| 阶段 | 尝试/成功 | 已知 token |
|---|---:|---:|
| 原生图索引 | 15/15 | 39,257 |
| mix 关键词 | 16/8 | 6,435 |
| naive 回答 | 16/8 | 12,190 |
| mix 回答 | 8/8 | 20,393 |
| 输出格式修订补测 | 6/6 | 12,078 |

索引完成后最初一次密集查询撞到了每分钟限额。保留 16 次失败记录后，改成至少 7 秒间隔、单次限流恢复，复用索引完成；未重置账本，也没有反复重建图。80 次实验上限内结束。

此前三轮抽取试验的 60 次请求、已知 168,245 token、1 次未知用量仍单独保留；两部分合计已知 258,598 token、121 次 LLM 尝试、17 次未知用量。**这不是整个项目历史总费用**，不覆盖更早 GraphRAG 与其他接口试验。

复现目录：服务器 `/data/xuancheng/retrieval_pilot_20261020`；本地同名 results 目录。关键文件：

- `run_retrieval.py`、`run_config.json`、`installed_requirements.txt`：执行和配置。
- `corpus.json`、`questions_with_review_targets.json`：材料、问题与未发给模型的评审目标。
- `graph_export.json`、`index/`：实际索引与图。
- `retrieval/`、`contexts/`、`answers/`：召回、实际模型上下文与原始答案。
- `semantic_review.json`、`comparison_metrics.json`：逐主张/逐题结论和机械统计。
- `answers_contract_v2/`、`contract_v2_review.json`：修订补测。
- `http/`、`provider_budget.json`、`usage_by_phase.json`：无密钥的请求、响应和用量。

所有结论是 AI 辅助审查，不是专家盲审；8 题沿用已见方法边界，是开发回归。当前样本小、文档短、没有独立无答案题和复杂跨文档必需链，不足以证明任一种方法具有普遍优势。
